# 软件本地化与应用内语言切换

> 状态：已完成，用户确认本地化可用。`swift build`、`swift build --build-tests` 通过；非 GUI 测试代码已编译但未执行。

## 产品范围

- 英文为主、简体中文为自带第二语言。
- onboarding 首步与设置中心共用语言选择器：跟随系统 / English / 简体中文。
- 两个窗口共享持久化偏好，切换立即生效，不要求关闭窗口或重启应用。
- 语言切换不重置向导步骤、设置导航、搜索、选择或确认弹窗的本地状态。

## 实现

1. **资源**：SPM `defaultLocalization: "en"` + `.process("Resources")`；经典 `.strings` 按 Onboarding / Settings / Menus / Runtime / Labels 分表，en 与 zh-Hans 各一套。lproj 加载兼容 SPM 的小写目录名。
2. **语言真值**：`@Observable L10nManager` 持有不可变 `Localization` 快照；偏好、实际语言和 bundle 一次替换。偏好变化即发布，即使“跟随系统”与显式选择解析到同一语言。跟随系统按首选语言的 zh 前缀归 zh-Hans，其余归 en。
3. **SwiftUI**：两个 hosting root 统一包裹 `LocalizedContent`，注入语言快照与 locale；直接查词的消费视图声明 `@Environment(\.l10n)`。`ForEach` 的枚举标签使用 `LocalizedText`，语言选项使用独立环境消费者。字符串查找不依赖隐式全局状态，不用 `.id(language)` 重建视图树。
4. **AppKit**：状态栏菜单、窗口标题订阅提交后的语言通知；已展开潮涌的无标题窗口文案随通知重绘；应用右键菜单在打开时读取当前快照。
5. **失败状态**：自有 Dock 错误以结构化语义和参数保存，显示时查词；外部系统错误描述保持原文。日志固定使用英文。
6. **验证边界**：权限轮询只在权限值变化时发布，不能承担语言刷新。`TideBarTests` 直接依赖可执行模块，覆盖语言解析、同语言下的偏好切换、Observation 发布、AppKit 通知时序、真实资源、枚举词条和错误文案；这些非 GUI 测试不证明原生控件的显示刷新。

## 回归检查参考

以下清单供后续回归使用，不代表本次逐项执行记录。用户执行 `swift run` 后按需检查，无需为语言验证启用 Dock 接管或修改系统设置。

- [ ] onboarding 首步反复切换 English / 简体中文 / 跟随系统，确认选择器显示、菜单勾选、正文、演示占位、底部按钮同时变化。
- [ ] 当系统语言为英文时切换“跟随系统 ↔ English”（中文系统则“跟随系统 ↔ 简体中文”），实际译文不变，但选中项必须正确改变。
- [ ] 设置“外观与交互”反复切换语言，检查主题、图标大小、亮度、动画、减少动态效果和全屏行为的所有选项标签；点击选项仍能正常修改偏好。
- [ ] 同时打开两个窗口，在设置切换语言，确认 onboarding 当前步骤同步刷新且不跳回首步；在 onboarding 切换，确认设置的当前页面（含关于页）同步刷新且导航不重置。
- [ ] 设置打开“添加应用”面板，输入搜索并选择应用，再从 onboarding 切换语言：保留搜索与选择，按钮和已有列表行文案同步刷新。
- [ ] 检查状态栏菜单、应用右键菜单、已有操作横幅、窗口标题的语言；如遇自有 Dock 错误，切换后应翻译，系统原生错误保持原文。无需人为制造系统操作失败。
- [ ] 关闭再打开窗口、退出再启动，确认语言偏好持久化；两种语言下无截断或原始 key。

可选执行非 GUI 用例：`swift test --filter TideBarTests`。这些用例不启动应用、不写实际偏好、不操作系统 Dock。
