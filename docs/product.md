# 产品

macOS 不占屏幕的窗口任务栏：平时缩成屏幕底部一条细线，光标靠近时如潮汐般展开。

解决系统 Dock 的三个痛点：占据底部空间（小屏 MacBook 利用率差）、窗口管理低效（最小化窗口难见难还原）、不反映窗口状态（只有运行点没有窗口）。不追求复刻 Dock 的全部功能。

目标用户：屏幕空间紧张的小屏 MacBook 用户；多窗口多任务、讨厌常驻界面噪音的人。对外文案参考见 [copy.md](copy.md)（占位初稿，未经审核定稿）。

## 灵魂交互

- 空闲时缩成 2~3pt 细线（随亮暗模式自适应的胶囊，即「汐线」）贴屏幕底边
- 鼠标进入热区展开为图标栏，离开后收起
- 核心差异化 = 零存在感 + 窗口管理：窗口状态点点可见、点击即达
- 汐线的通知感知：新角标到达细线轻涌一次，未确认期间持续涟漪发散，展开即确认——不靠抢占注意力表达「有事」，靠持续在场表达「还没被知道」
- 汐线的应用收纳：应用进入运行态时，细线中心固定、轻轻向内收拢并增厚，再柔和恢复；一次性表达「已收纳」，连续启动合并，展开态由图标反馈接管

## 条目与固定

- TideBar 承载条目（item），不限于应用；所有 item 都是资源或能力的虚拟投射，不是本体。条目类型决定行为，固定状态决定是否持久保留，两者正交。
- 固定项由用户维护，可以是应用、文件、目录；模型允许小组件或更多类型接入，各类型拥有自己的行为，不强制套用应用窗口语义。
- 临时项来自运行中的应用；固定应用与临时应用共用同一套窗口状态与操作，同一应用只显示一次。普通应用退出后，固定项保留，临时项消失；Finder 的逻辑运行规则见 [decisions.md](decisions.md)。
- 支持拖拽调整固定顺序、拖出并松手取消固定、从外部拖入固定：`.app` 识别为应用，文件与目录保留各自类型。取消固定不删除资源、不退出应用。
- 拖拽会话独立于栏的展开状态：正常模式下离开可收起，返回热区可再次展开；收起不取消拖拽，拖出边界不立即修改固定状态。
- 拖拽先区分来源：从 TideBar 内部发起，无论条目是否固定，都只管理引用的重排或移除，不移动本体、不向另一 item 交付资源执行动作。
- 外部资源拖到空白处（包括图标之间）创建关联 item，本体不进入 TideBar；拖到图标上则触发目标的接收行为，例如应用打开资源、目录移动资源。操作持有源与目标的引用，是否解析实际对象由行为自行决定，也可以直接处理引用；一次松手只执行一个意图，悬停不提前执行。插入与目标接收具有可区分的反馈。

## 窗口管理

- 应用条目以 app 图标为粒度，不平铺窗口；图标下方点点反映窗口状态（实心=活跃窗口、空心=最小化）
- 点击图标 = 切换该 app 最近窗口；长按或 ⌥+点击 = 「潮涌」展开窗口列表
- 潮涌列表以窗口标题为主、文档图标增强，点击直达任意窗口（含最小化，点击即还原）——用更好的方案还原被 Dock 带走的能力
- 隐藏系统 Dock 后失去落点的最小化窗口由潮涌接替，不再无家可归

## 边界

- 不做废纸篓与窗口预览（决策见 [decisions.md](decisions.md)）。固定管理只修改引用；向目标 item 投递资源是独立操作，目录接收可移动资源，不能因固定／取消固定意外改变原文件。
- 通用固定项首批覆盖应用、文件、目录；小组件与更多类型保留扩展位置，具体能力另行立案。
- 通知角标是例外：经 Dock AX 镜像提供（路线与成本见 [decisions.md](decisions.md)），配合汐线涟漪形成自有通知语言
- 不提供 App 任务进度反馈：不读取 App 内部信息，也不要求第三方 App 适配；系统没有可用的跨 App 统一进度 API
- 系统级功能不自绘（依据见 [decisions.md](decisions.md)），精力全部花在差异化交互与窗口体验上

## 命名

- TideBar（目录/bundle 用 ASCII），中文显示名「汐」
- 概念词：收起态细线「汐线」（EN Tide Line）；展开态图标栏「图标栏」（EN icon bar）；二级窗口展开「潮涌」（代码标识 Surge）——汐为收敛态，涌为突发态
- 同名 iOS 潮汐监测 App（2024，海洋气象类）无实质冲突；上架前需复审产品名

## 对标

- uBar（窗口任务栏形态）、DockDoor（窗口预览）；开源方案调研见 [research-dock-alternatives.md](research-dock-alternatives.md)
- 无现成产品做过「细线收起态」交互，差异化成立
